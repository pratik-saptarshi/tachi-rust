tachi-rust input contract

Pre-requisites

This document lists the inputs and environment prerequisites that produce the best analysis outcomes from tachi-rust CLI commands and MCP-backed runs. It is optimized for both human review and machine parsing.

architecture threat-model risk-score compensating-controls infographic security-report MCP-compatible

Quick Input Checklist

Provide these first. They are the minimum high-value inputs for a clean pipeline.

  • Architecture file: docs/security/architecture.md or an equivalent supported format.
  • Threat output: threats.md or threats.sarif as the canonical threat-model artifact.
  • Risk output: risk-scores.md or risk-scores.sarif for quantitative prioritization.
  • Codebase path: the real target repository when analyzing compensating controls.
  • Co-located baseline: keep threats.md beside downstream artifacts for infographic and PDF assembly.
  • Tooling: install typst and mmdc; set GEMINI_API_KEY only if JPG images are desired.

What tachi-rust Needs

Best outcome principle

tachi-rust analyzes architecture first, then enriches the result through downstream artifacts. The more complete and specific the input bundle, the better the analysis, scoring, residual risk, visuals, and final PDF output.

For MCP-backed runs

Pass file paths and project paths, not raw file bodies, whenever the workflow supports on-demand file reads. That keeps context smaller and lets the analysis stages load only what they need.

Command Input Requirements

Command Required inputs Optional but high-value inputs Why it matters
/tachi.architecture Target codebase or project documentation Existing architecture draft, infra files, API specs, environment configs Produces the structured architecture file that downstream commands consume.
/tachi.threat-model Architecture description file Existing baseline threats.md from a prior run, explicit trust boundaries, data flows, auth zones, agent or MCP surfaces Generates the primary findings artifact and supports delta tracking when a baseline exists.
/tachi.risk-score threats.md or threats.sarif architecture.md for reachability context Adds quantitative scoring, governance fields, and SARIF output for triage and CI integration.
/tachi.compensating-controls risk-scores.md or risk-scores.sarif, plus the target codebase path architecture.md for better mapping, a fully indexed target tree, and stable file layout Detects implemented defenses, calculates residual risk, and recommends missing controls.
/tachi.infographic One of compensating-controls.md, risk-scores.md, or threats.md Co-located threats.md when the primary source is risk or controls output, and GEMINI_API_KEY for JPGs Creates the richest possible visual based on the best available source tier.
/tachi.security-report threats.md, plus typst installed risk-scores.md, compensating-controls.md, attack trees, attack chains, infographic JPGs, brand assets, mmdc Assembles the final PDF booklet and conditionally includes richer pages when artifacts exist.

What to Put Inside the Architecture Input

Must include

  • Components, services, agents, servers, queues, databases, and external entities.
  • Data flows, protocols, trust boundaries, and authentication or privilege transitions.
  • Any LLM, agent, tool server, plugin, or MCP surface if the system has one.
  • Data stores, secrets handling, egress paths, and boundary-crossing integrations.
  • Deployment or environment differences that affect exposure or access control.

Worth adding

  • Known mitigations already present in the codebase.
  • Tenant, group, or project scoping rules.
  • Input validation, serialization, and output encoding boundaries.
  • Any current limitations, assumptions, or security exceptions.
  • Previous analysis output if you want change detection and baseline comparisons.

Operational Prerequisites

Prerequisite Expectation Notes
tachi agents installed .claude/agents/tachi/ contains the shipped agents and templates Without the agents, the slash commands halt before analysis begins.
Typst CLI typst is available on PATH Required for PDF generation.
Mermaid CLI mmdc is available on PATH Required when attack trees or attack chains need rendering.
Gemini API key GEMINI_API_KEY set in the environment Optional. Enables JPG infographic generation only.
Writable output location Target directory exists and can be written by the current session Use the default docs/security/ pipeline layout or a custom output path.
Optional baseline Previous timestamped run folder with threats.md Improves delta reporting and makes findings easier to compare across runs.

Best-Practice Input Bundle

{
  "architecture": "docs/security/architecture.md",
  "baseline_threats": "docs/security/<previous-timestamp>/threats.md",
  "threat_model_output": "docs/security/<current-timestamp>/threats.md",
  "risk_output": "docs/security/<current-timestamp>/risk-scores.md",
  "controls_output": "docs/security/<current-timestamp>/compensating-controls.md",
  "target_codebase": "/absolute/path/to/project",
  "tooling": {
    "typst": true,
    "mmdc": true,
    "gemini_api_key": "optional"
  }
}

The exact filenames can vary by output directory, but keeping the artifacts co-located and timestamped is the cleanest way to preserve baselines and feed every downstream command.

Machine-readable hint: the page includes an application/ld+json ItemList and data-prereq-id attributes for downstream parsing.
